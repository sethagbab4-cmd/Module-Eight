The Gaming room wanted to develop a software application based on the existing game, Draw It or Lose It. The client needed a program to support multiple teams and players, as well as to keep track of game names and IDs. The goal was to design a software that could manage the game sessions and be distributed to multiple operating platforms. I think one thing I did well was clearly explaining the software requirements for each system. Working through the design document gives a plan to follow when developing code. Instead of trying to write all the code at once, it could be broken into smaller and more manageable parts. This makes it easier to identify errors and understand how the classes interact. It is important to consider the user's needs because the software has to address the client's problems. Understanding their needs helps prevent adding features that aren't needed. This reduces mistakes later on and the need for major changes.
